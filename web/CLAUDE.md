## 异常处理
严禁吞掉 Error。所有模块必须显式抛出异常或使用全局错误边界处理，确保错误追踪链路完整。

## 代码原则
- All typing pass
- DRY，改动最小化
- 不要为了解决问题打短期补丁
- 不过度抽象
- 定期删除无用代码，不堆屎山

## 模块化边界
代码必须高度模块化，边界清晰。每个功能点开发前需确认输入、输出及对接协议。

## 新 Thread 启动
开启新对话后，第一件事是读取 handoff.md 以恢复项目上下文。

## 文档规范
每次功能变更/增加/减少/bugfix，或者技术选型调整/产品feature变化时，必须同步更新文档，路径规范如下：
技术文档：docs/tech/xxx.md (包含输入输出、接口定义、对接方法)。
产品逻辑：docs/product/xxx.md (描述业务逻辑、Feature 变化)。
README: 项目介绍，如何把项目跑起来，有哪些运行方式等，不要加入项目细节
要求：文字简洁、干练、清晰

## 交付闭环
1. 更新文档：根据变更内容同步更新 docs/tech/ 或 docs/product/ 下的对应文档。
2. E2E 或者单测全部通过
3. Commit：按 Git 规范提交，一个 Feature 一个 Commit，保持小粒度提交
feature: 新功能
fix: 修复问题
refactor: 代码重构
chore: 杂事/依赖更新

# 上下文继承
输入 /handoff 指令时，必须更新 handoff.md，内容包含：
- Session 总结：本次对话完成了什么。
- 踩坑记录：开发过程中遇到的坑及解决方案。
- 环境配置：已配置好的 API Keys, Env 变量预览（脱敏）。
- 运行方式：最新的项目启动与测试指令。
- 当前环境：本机安装好的工具，cli，docker等概述，让下一个agent可以直接使用
- 文档索引：文档路径
- 待办事项：未解决的问题、当前进展、下一阶段建议。
注：自动删除过时信息，保持 handoff 简洁，完整。
